## ロボット監視・リプレイシステム — 実装基盤構築計画

SPEC.md に従い、ClaudeDesign（FE）とCodex（BE）が並行で開発できるフルスタック基盤を構築する。今回は「足場 + 主要API + 1ルート結合（Pane追加→LIVE→REPLAY→事故保存）」を到達点とする。

### 技術スタック（確定）
- **FE**: Vite + React 18 + TypeScript / Tailwind CSS + shadcn/ui / Zustand（状態管理）+ HLS.js（LL-HLS再生）/ MSW（APIモック）
- **BE**: Python 3.14 + FastAPI / tomllib（TOML読込）/ SQLite（動的ソース・事故保存、Python標準）/ httpx（MediaMTX REST制御・RTSP疎通）
- **基盤**: docker-compose（MediaMTX + ffmpeg テスト用RTSPソース）/ npm workspaces（FEモノレポ）
- **時刻**: 内部UTC、表示Asia/Tokyo（NFR-005）

### 実装ステップ（実行順）

**Step 1 — ルート基盤**
- `docker-compose.yml`: MediaMTX（RTSP取り込み/HLS配信/fMP4録画・2h保持）+ ffmpeg テストソース3本（SPEC 7.1の3カメラ想定）。`config/mediamtx.yml` で録画パス・保持時間・リング設定を宣言。
- `config/sources.toml`: SPEC 7.1の3ソース + 認証情報の環境変数参照例
- `.env.example`, `.gitignore`, `README.md` 雛形

**Step 2 — バックエンド（Codex範囲の骨格）**
- FastAPI app + `/api/v1` プレフィックス + CORS（LAN）
- `errors.py`: 23章エラーハンドラ（code定数・requestId付与）
- `toml_loader.py`: tomllibで常設ソース読込、環境変数でRTSP URL構築
- `source_store.py`: SQLite動的ソース（一時/永続）・重複検知
- `rtsp_probe.py`: ffprobeで接続テスト（codec/width/height/fps・6種エラー判定）
- `mediamtx.py`: REST ラッパ（path定義・録画ON・HLSパス生成）
- 各router（22.1〜22.9全エンドポイント）。22.5/22.7はMediaMTXの相対URLを返す（フロントがMediaMTX固有URLを組まない：SPEC 22.7注記）
- `recording_ranges.py`: fMP4セグメント走査でavailableFrom/To・ranges/欠損
- `monitor.py`: バックグラウンドタスクで切断(5s/15s)・録画停止・ディスク(80%/90%)検知
- `incident.py`: MP4独立保存（リング保護）
- pytest: 正常系 + 23章代表エラーコード

**Step 3 — フロントエンド型・状態・モック（ClaudeDesignの受け皿）**
- 手書き型（`types/`）: PaneState・WorkspaceState・Source・RecordingRange・ConnectionTest・各API型・ApiError/ErrorCode
- API client: fetchラッパ、23章エラー形式の正規化、認証情報を一切保持しない（FR-004/NFR-003）
- Zustand `workspace.ts`: panes/selectedPaneId/syncMode/layout、persistで復元（FR-029）、RTSP URLをlocalStorageに保存しない（NFR-003）
- MSW handlers: 22章全エンドポイントの正常 + 25章の各状態（接続失敗/録画停止/容量不足等）のモック
- Tailwind + shadcn/ui 初期化、ダークな監視UI向けトークン（LIVE/REPLAY/エラー状態色）

**Step 4 — 1ルート結合の画面スケルトン**
- `LayoutGrid`（Pane数→1×1/2×1/2×2/3×2 自動切替：9章）
- `Pane`/`PaneHeader`（18章要素：名前・LIVE/REPLAY・接続状態・最大化・メニュー・削除）
- `AddPaneDialog`（17章：登録済みタブ + URL入力タブ + 接続テスト表示）
- `useLivePlayer`/`useReplayPlayer`（HLS.js・再接続ロジック）
- `Timeline`（15章：現在時刻・2h・目盛り・録画区間・欠損）
- `CommonControls`（20章再生操作 + 操作対象表示：FR-025）
- `IncidentDialog`（19章）
- 結合ルート: Pane追加 → LIVE表示 → タイムラインで過去へ → REPLAY → ライブへ戻る → 事故保存

**Step 5 — README 完成**
- セットアップ（docker compose up + uvicorn + npm dev）
- TOML設定方法・環境変数認証（SPEC 7.1）
- 開発フロー（ClaudeDesignがUIを置き換える場所の明示）

### SPEC準拠の主要ポイント（実装で担保）
- **NFR-003 セキュリティ**: RTSP URL/認証をフロントへ返さない・localStorage/ログ/URLクエリに残さない。client/storeで明示禁止
- **FR-004**: RTSP URLはフロント保持せず即バックエンド送信
- **FR-029/NFR-005**: Workspace復元は可能だが認証URLは保存しない、内部UTC/表示JST
- **22.7注記**: フロントがMediaMTX固有URLを組まない（バックエンドが生成）
- **10章 PaneState**: 真偽値の組み合わせで状態を推測しない（明示的playerState）
