# ロボット監視・リプレイシステム 要件定義書

## 1. 文書の目的

本書は、ロボットの動作状況を複数のカメラ映像で監視し、直近2時間の映像を任意の時刻から再生できるWebシステムの要件を定義する。

実装担当は以下を想定する。

* フロントエンド設計・実装：ClaudeDesign
* バックエンド・映像基盤実装：Codex
* 映像入力：RTSP対応カメラ
* 映像中継・録画基盤：MediaMTX
* 設定ファイル：TOML
* 実行環境：ローカルネットワーク内のLinux PCまたはNUC

本システムでは、ユーザーが監視画面上へPaneを追加し、登録済みのカメラを選択するか、RTSP URLを直接入力することで映像を表示できることを重視する。

---

# 2. システムの目的

本システムは、ロボットの運転・開発・障害解析において、以下を可能にする。

1. RTSPカメラのライブ映像を表示する
2. 1画面から最大6画面まで同時に表示する
3. ユーザーが必要な映像をPaneとして追加する
4. TOMLへ登録済みのカメラを一覧から選択する
5. 未登録のRTSP URLを直接入力して一時的に表示する
6. 各カメラについて直近2時間の映像を保持する
7. 各Paneをライブまたは過去映像の状態で表示する
8. 複数カメラの過去映像を同一時刻で同期再生する
9. 異常発生時の映像を自動削除対象外へ保存する
10. カメラ切断、録画停止、容量不足を検知する

本システムは、ロボットの制御、安全制御、非常停止機能を提供するものではない。

---

# 3. 基本コンセプト

本システムにおける主要な操作単位はカメラ管理画面ではなく、監視画面上のPaneとする。

ユーザーの操作イメージは以下とする。

```text
監視画面を開く
    ↓
「Paneを追加」を押す
    ↓
登録済みカメラを選ぶ
または
RTSP URLを入力する
    ↓
Paneへ映像が表示される
    ↓
必要に応じてライブから過去映像へ切り替える
```

ユーザーに対しては「映像をPaneへ追加する」という単純な操作として見せる。

内部では、以下の処理をバックエンドが担当する。

```text
Pane追加要求
    ↓
映像ソースの選択または作成
    ↓
RTSP接続
    ↓
MediaMTXへの登録
    ↓
ライブ配信URL生成
    ↓
録画開始
    ↓
Paneへ再生情報を返却
```

ブラウザからRTSP URLを直接再生してはならない。

RTSP映像は必ずバックエンドおよびMediaMTXを経由し、ブラウザで再生可能な方式へ変換または中継する。

# 4. 用語定義

## 4.1 Pane

監視画面上に配置される1つの映像表示領域。

Paneはカメラそのものではなく、「特定の映像ソースを、どの状態で表示しているか」を表す。

Paneは以下の情報を持つ。

* Pane ID
* 選択中の映像ソース
* LIVEまたはREPLAY
* 再生時刻
* 再生状態
* 再生速度
* ミュート状態
* 選択状態
* 最大化状態
* エラー状態

同一の映像ソースを複数のPaneへ追加してもよい。

例：

```text
Pane 1：ロボット全体カメラのLIVE
Pane 2：ロボット全体カメラの15分前
Pane 3：搬送部カメラの15分前
```

## 4.2 映像ソース

RTSP URLによって取得されるカメラ映像。

映像ソースには以下の種類がある。

* 登録済みソース
* 一時ソース
* UIから永続登録したソース

## 4.3 登録済みソース

TOML設定ファイルへあらかじめ登録された映像ソース。

監視画面のPane追加時にプルダウンから選択できる。

## 4.4 一時ソース

ユーザーがRTSP URLを直接入力して追加した、現在の実行中だけ有効な映像ソース。

アプリケーション再起動後は一覧へ残らなくてもよい。

## 4.5 LIVE

現在のカメラ映像を表示する状態。

MVPでは約3秒程度の遅延を許容する。

## 4.6 REPLAY

保存された過去映像を、指定された日時から再生する状態。

## 4.7 Workspace

現在開いているPaneの集合と、その配置、同期状態、選択状態を含む監視作業空間。

# 7. 映像ソース設定

## 7.1 TOML設定

登録済み映像ソースはTOMLで定義できること。

例：

```toml
[[sources]]
id = "robot-overview"
name = "ロボット全体"
rtsp_url = "rtsp://192.168.1.20:554/main"
enabled = true

[[sources]]
id = "part-unit"
name = "部品供給部"
rtsp_url = "rtsp://192.168.1.21:554/main"
enabled = true

[[sources]]
id = "conveyor"
name = "搬送部"
rtsp_url = "rtsp://192.168.1.22:554/main"
enabled = true
```

認証情報を含む場合、平文パスワードをGit管理対象のTOMLへ直接記載することは避ける。

推奨形式：

```toml
[[sources]]
id = "robot-overview"
name = "ロボット全体"
host = "192.168.1.20"
path = "/main"
username_env = "ROBOT_CAMERA_USERNAME"
password_env = "ROBOT_CAMERA_PASSWORD"
enabled = true
```

バックエンドが環境変数を読み込み、RTSP URLを構築する。

## 7.2 TOMLの役割

TOMLは以下の用途に限定する。

* 常設カメラの初期設定
* Gitで管理する設備設定
* 手動編集する固定設定
* 起動時に読み込む設定

UIから追加した映像ソースによって、実行中にTOMLを直接書き換えてはならない。

UIから永続登録する場合は、SQLiteまたは別の動的設定ファイルへ保存する。

## 7.3 映像ソース統合

Pane追加時の選択肢には以下を統合して表示する。

```text
TOML登録済みソース
+
UIから登録した永続ソース
=
登録済みソース一覧
```

一時ソースは、現在のWorkspace内でのみ表示されてもよい。

# 8. Pane機能要件

## FR-001 Pane追加

ユーザーは監視画面へPaneを追加できること。

最大Pane数は6とする。

Pane数が6の場合、追加操作は無効化し、理由を表示する。

表示例：

```text
最大6画面まで表示できます
```

## FR-002 Pane追加方法

Pane追加時、以下の方法を選択できること。

1. 登録済み映像ソースから選択
2. RTSP URLを直接入力

初期選択は登録済み映像ソースとする。

## FR-003 登録済み映像ソース選択

Pane追加ダイアログには、登録済み映像ソースをプルダウンまたは検索可能な一覧で表示する。

各候補には以下を表示する。

* 表示名
* 接続状態
* 任意で設置場所
* 任意で解像度
* TOML登録またはUI登録の区別

選択後、原則として1操作でLIVE Paneを追加できること。

## FR-004 RTSP URL直接入力

ユーザーはRTSP URLを直接入力できること。

入力項目：

* 表示名
* RTSP URL
* 永続登録するか
* 任意の説明

例：

```text
表示名：実験用カメラ
RTSP URL：rtsp://192.168.1.30:554/main
```

RTSP URLはフロントエンドで保持し続けず、バックエンドへ送信する。

フロントエンドのログ、ブラウザコンソール、URLクエリ、localStorageへ、認証情報付きRTSP URLを保存してはならない。

## FR-005 接続テスト

RTSP URLを直接入力した場合、Paneへ追加する前に接続テストを実行できること。

接続テストでは可能な範囲で以下を確認する。

* URL形式
* ネットワーク接続
* 認証成功
* 映像ストリーム存在
* コーデック
* 解像度
* フレームレート

結果例：

```text
接続成功
H.264
1920 × 1080
15 fps
```

失敗時は原因を可能な範囲で区別する。

* URL形式不正
* 接続タイムアウト
* 認証失敗
* ストリームなし
* 未対応コーデック
* MediaMTX登録失敗

## FR-006 一時登録と永続登録

RTSP URL入力時に以下を選択できること。

* このWorkspaceでのみ使用する
* 次回以降も登録済みソースへ表示する

一時登録の場合：

* アプリケーション再起動後に消えてよい
* 現在のWorkspaceで利用できる
* TOMLへは保存しない

永続登録の場合：

* 動的設定ストレージへ保存する
* 次回起動後も一覧へ表示する
* 同一URLの重複登録を検知する

## FR-007 Pane削除

各Paneを個別に削除できること。

Pane削除時に映像ソースそのものを削除してはならない。

一時ソースがどのPaneからも参照されなくなった場合、バックエンドは一定時間後に接続を終了してよい。

## FR-008 Pane並べ替え

ユーザーはドラッグ操作などでPaneの順序を変更できること。

MVPではPaneの任意リサイズは不要とする。

## FR-009 Pane最大化

任意のPaneを一時的に最大表示できること。

最大化を解除すると元のレイアウトへ戻ること。

最大化中も他のPane状態を破棄しない。

## FR-010 Pane選択

常に1つのPaneを選択中Paneとして扱う。

選択中Paneは枠、ヘッダー、背景などで明確に示す。

共通再生操作は、原則として選択中Paneへ適用する。

同期モード中は、操作対象が同期対象Paneであることを表示する。

---

# 9. レイアウト要件

Pane数に応じて、自動的にグリッドレイアウトを変更する。

推奨初期レイアウト：

```text
1 Pane：1 × 1
2 Pane：2 × 1
3 Pane：2 × 2
4 Pane：2 × 2
5 Pane：3 × 2
6 Pane：3 × 2
```

3 Pane時の空き領域は、Pane追加領域として表示してよい。

例：

```text
┌──────────────┬──────────────┐
│ Pane 1       │ Pane 2       │
├──────────────┼──────────────┤
│ Pane 3       │ ＋ Pane追加   │
└──────────────┴──────────────┘
```

画面幅が不足する場合は、映像の最小表示サイズを維持しつつ、全体スクロールまたはレスポンシブ配置を行う。

# 10. Pane状態

各Paneは最低限、以下の状態を持つ。

```ts
type PaneState = {
  id: string
  sourceId: string | null

  mode: "LIVE" | "REPLAY"

  playerState:
    | "INITIALIZING"
    | "CONNECTING"
    | "PLAYING"
    | "PAUSED"
    | "RECONNECTING"
    | "UNAVAILABLE"
    | "ERROR"

  replayAt: string | null
  playbackRate: 0.5 | 1 | 2 | 4

  muted: boolean
  selected: boolean
  maximized: boolean

  errorCode: string | null
}
```

複数の真偽値を組み合わせて再生状態を推測する設計は避ける。

悪い例：

```ts
isLoading
isPlaying
isLive
isReplay
isError
```

これでは相互に矛盾した状態が発生しやすい。

# 11. LIVE表示要件

## FR-011 LIVE表示

Pane追加時の初期表示は原則としてLIVEとする。

LIVE Paneには以下を表示する。

* カメラ名
* LIVEラベル
* 接続状態
* 録画状態
* 遅延状態
* 最大化操作
* Paneメニュー
* Pane削除操作

表示例：

```text
ロボット全体    ● LIVE
```

## FR-012 LIVE遅延

MVPでは約3秒程度の遅延を許容する。

本システムの映像は安全制御の代替として使用しない。

将来的に低遅延化する場合も、録画機能とライブ表示機能を分離した構造を維持する。

## FR-013 LIVE接続失敗

映像取得失敗時に黒画面だけを表示してはならない。

表示例：

```text
カメラに接続できません
最終映像受信：19:32:14
再接続を試行しています
```

# 12. 録画要件

## FR-014 常時録画

登録され、有効化された映像ソースについて常時録画を行う。

一時ソースについては、Pane追加後から録画を開始してよい。

録画はMediaMTXを利用する。

## FR-015 2時間保持

各映像ソースについて、現在時刻から直近2時間の録画を保持する。

2時間を超えたリング録画は自動削除する。

初期設定値：

```text
保持時間：2時間
録画セグメント：1分
内部パート：1秒程度
録画形式：fMP4
```

保持時間は設定変更可能とするが、MVPの標準値は2時間とする。

## FR-016 録画欠損

システムは、常に2時間分の録画が存在すると仮定してはならない。

カメラ切断、再起動、ネットワーク障害などにより、録画が存在しない区間を扱えること。

録画範囲APIは以下を返せること。

* 最古の録画時刻
* 最新の録画時刻
* 録画が存在する区間
* 録画が存在しない区間

---

# 13. REPLAY機能要件

## FR-017 REPLAYへの切り替え

任意のPaneをLIVEからREPLAYへ切り替えられること。

切り替え方法：

* タイムライン上の時刻を選択
* 日時を直接指定
* 10秒戻る
* 1分戻る
* 異常イベントを選択

## FR-018 特定状態でPaneを追加

Pane追加時に、以下の状態を指定できること。

* LIVEで追加
* 指定時刻のREPLAYで追加
* 再生状態で追加
* 一時停止状態で追加
* 再生速度

例：

```text
搬送部カメラを
2026年7月10日 19:32:10から
一時停止状態で
1倍速で追加
```

イベント起点で追加する場合、イベント発生時刻より一定時間前から表示できること。

初期値：

```text
イベント発生30秒前
```

## FR-019 REPLAY表示

REPLAY Paneには以下を表示する。

* REPLAYラベル
* 再生日時
* 現在時刻との差
* 再生速度
* 再生状態
* ライブへ戻る操作

例：

```text
REPLAY
2026年7月10日 19:32:10
現在より12分34秒前
```

過去映像をLIVEとして表示してはならない。

## FR-020 再生操作

最低限、以下を提供する。

* 再生
* 一時停止
* 10秒戻る
* 10秒進む
* 1分戻る
* 1分進む
* 任意時刻へ移動
* ライブへ戻る
* 再生速度変更

再生速度：

```text
0.5倍
1倍
2倍
4倍
```

4倍再生が安定しない場合、MVPでは2倍までを必須とする。

## FR-021 ライブへ戻る

REPLAY Paneは1操作でLIVEへ戻せること。

ボタン名：

```text
ライブへ戻る
```

録画の末尾へ到達しても、自動的にLIVEへ切り替えない。

ユーザーの明示操作によって切り替える。

# 14. 複数Pane同期再生

## FR-022 独立再生

同期モードが無効の場合、各Paneは独立した状態を持つ。

例：

```text
Pane 1：LIVE
Pane 2：10分前を再生
Pane 3：20分前で一時停止
Pane 4：LIVE
```

## FR-023 同期再生

ユーザーはREPLAY中の複数Paneを同一時刻で再生できること。

MVPでは以下の2モードを提供する。

```text
INDEPENDENT
SYNCED
```

### INDEPENDENT

各Paneを個別に操作する。

### SYNCED

すべてのREPLAY Paneを同じ基準時刻で操作する。

同期対象Paneは以下の状態を共有する。

* 基準時刻
* 再生・一時停止
* 再生速度
* 10秒移動
* 1分移動
* タイムライン移動

## FR-024 LIVE Paneの同期除外

SYNCEDモードでも、LIVE Paneは同期再生の対象にしない。

例：

```text
Pane 1：LIVE
Pane 2：REPLAY 19:32:10
Pane 3：REPLAY 19:32:10
```

この場合、Pane 2とPane 3のみが同期する。

全Paneを過去時刻へ移動する操作を行った場合、LIVE PaneをREPLAYへ切り替える確認を表示する。

## FR-025 同期操作対象表示

共通操作領域には、操作対象を明示する。

例：

```text
操作対象：選択中Pane
```

または：

```text
操作対象：同期中の3 Pane
```

操作対象を表示せず、複数Paneを一括操作してはならない。

# 15. タイムライン要件

## FR-026 共通タイムライン

画面下部に直近2時間の共通タイムラインを表示する。

タイムラインには以下を表示する。

* 現在時刻
* 2時間前
* 時刻目盛り
* 選択中Paneの再生位置
* 録画存在区間
* 録画欠損区間
* 事故イベント
* 将来的なロボットイベント
* LIVE位置

同期モード時は、同期対象Paneの共通再生位置を表示する。

## FR-027 録画範囲の差異

複数カメラ間で録画範囲が異なる場合、その差異を表現すること。

同期時刻に録画が存在しないPaneでは、以下を表示する。

```text
この時刻には録画がありません
```

他のPaneの再生は継続できること。

1つのPaneの録画欠損によって、すべての同期再生を停止してはならない。

# 16. Workspace要件

## FR-028 Workspace状態

Workspaceは以下を保持する。

```ts
type WorkspaceState = {
  panes: PaneState[]
  selectedPaneId: string | null
  syncMode: "INDEPENDENT" | "SYNCED"
  layout: 1 | 2 | 3 | 4 | 5 | 6
}
```

## FR-029 Workspace復元

ページ再読み込み後に、可能な範囲で以下を復元する。

* Pane数
* Pane順序
* 選択映像ソース
* LIVEまたはREPLAY
* 選択中Pane
* 同期モード

認証情報付きRTSP URLをlocalStorageへ保存してはならない。

一時ソースを復元できない場合は、復元不可であることをPane上へ明示する。

## FR-030 Workspace保存

MVPではWorkspace状態をブラウザ内へ保存してよい。

将来的にバックエンドへ保存できるデータ構造にする。

MVPではWorkspace共有機能は必須ではない。

# 19. 事故映像保存

## FR-031 事故映像保存

ユーザーは、任意のPaneの現在表示時刻を基準として映像を保存できること。

初期保存範囲：

```text
基準時刻の5分前から5分後
合計10分
```

保存項目：

* 映像ソース
* 基準時刻
* 開始時刻
* 終了時刻
* タイトル
* 保存理由
* メモ

保存理由：

```text
ロボット異常
品質不良
安全上の問題
通信障害
動作確認
その他
```

## FR-032 複数Pane事故保存

同期中の場合、同期対象となっている複数の映像ソースを同一事故として保存できることが望ましい。

MVPでは以下のいずれかを実装する。

1. 選択中Paneのみ保存
2. 同期対象Paneすべてを保存

どちらを保存するか、保存ダイアログで明示する。

## FR-033 保存映像保護

事故映像は2時間リングバッファの削除対象外とする。

事故映像は独立したMP4または独立した録画セグメントとして保存する。

元のリング録画が削除された後も再生できること。

接続失敗

# 24. 非機能要件

## NFR-001 性能

目標値：

* API応答：通常500ミリ秒以内
* Pane追加要求受付：1秒以内
* LIVE再生開始：通常3秒以内
* REPLAY開始：通常3秒以内
* 状態更新：5秒以内
* 事故保存要求受付：1秒以内

## NFR-002 複数Pane性能

最大6Paneを同時表示できること。

6Pane表示時は以下を許容する。

* 監視表示用の低解像度ストリーム使用
* 非選択Paneのフレームレート低下
* 最大化Paneのみ高解像度
* 非表示Paneの再生停止
* 音声の既定無効化

録画品質と監視表示品質を分離できる設計とする。

推奨例：

```text
録画：1080p、15fps
監視：720p、10fps
```

## NFR-003 セキュリティ

* RTSP認証情報をフロントエンドへ返さない
* 認証情報をGitへコミットしない
* 認証情報をログへ出力しない
* RTSP URLをブラウザURLへ含めない
* RTSP URLをlocalStorageへ保存しない
* APIは原則LAN内のみで公開する
* 任意のファイルパスをAPIで指定できない
* ディレクトリトラバーサルを防止する

## NFR-004 可用性

* バックエンド再起動後に復旧する
* MediaMTX再起動後に復旧する
* カメラ復旧後に録画を再開する
* 一部録画破損によって全録画を失わない
* 1つのPane障害によって他Paneを停止しない

## NFR-005 時刻

内部時刻はUTCで扱う。

ユーザー表示はAsia/Tokyoとする。

録画サーバー、カメラ、ロボット制御PCは時刻同期する。

# 27. 受け入れ条件

## AC-001 登録済みソース追加

* TOMLに登録した映像ソースが一覧へ表示される
* 一覧から選択してPaneへ追加できる
* PaneにLIVE映像が表示される

## AC-002 RTSP URL直接入力

* RTSP URLを入力できる
* 接続テストを実行できる
* 成功時に映像情報が表示される
* Paneへ追加できる
* 認証情報がブラウザへ残らない

## AC-003 一時ソース

* 一時ソースを追加できる
* 現在のWorkspaceで利用できる
* 再起動後に消えてもよい
* TOMLを書き換えない

## AC-004 1〜6 Pane

* 1Paneから6Paneまで表示できる
* Pane数に応じて自動レイアウトされる
* 6Pane時に追加操作が無効化される

## AC-005 Pane独立再生

* PaneごとにLIVEとREPLAYを切り替えられる
* 同じ映像ソースを別時刻で表示できる
* 1つのPane操作が他Paneへ影響しない

## AC-006 同期再生

* 複数REPLAY Paneを同一時刻へ移動できる
* 再生、一時停止、移動、速度を同期できる
* LIVE Paneは同期対象外になる
* 録画欠損Paneがあっても他Paneは再生できる

## AC-007 2時間録画

* 2時間以上連続録画できる
* 直近2時間を再生できる
* 古いリング録画が自動削除される
* 録画が継続する

## AC-008 障害検知

* カメラ切断を検知できる
* 録画停止を検知できる
* 容量不足を検知できる
* 復旧後に自動で正常状態へ戻る

## AC-009 事故映像保存

* 選択時刻前後の映像を保存できる
* 複数ソースを同一事故として保存できる
* 2時間経過後も再生できる
* 失敗時に理由が表示される

## AC-010 再起動

* バックエンド再起動後に復旧する
* MediaMTX再起動後に復旧する
* カメラ復旧後に映像表示と録画が再開する

# 28. 完了条件

以下をすべて満たした時点でMVP完成とする。

1. TOML登録済みカメラをPaneへ追加できる
2. RTSP URLを直接入力してPaneへ追加できる
3. RTSP接続テストができる
4. 1〜6 Paneを同時表示できる
5. PaneごとにLIVEまたはREPLAYを表示できる
6. 同一ソースを複数Paneへ追加できる
7. 複数REPLAY Paneを同一時刻で同期できる
8. 直近2時間を録画できる
9. 任意の録画時刻から再生できる
10. 録画欠損を表示できる
11. 事故映像を自動削除対象外へ保存できる
12. カメラ切断を検知できる
13. 録画停止を検知できる
14. ディスク容量不足を検知できる
15. プロセス再起動後に自動復旧できる
16. 異常系テストが実施されている
17. セットアップ手順と設定方法がREADMEへ記載されている

画面が表示され、映像が一度再生できただけでは完成としない。

監視システムとして必要な、録画継続、異常検知、再接続、録画欠損、事故保存まで動作して初めて完成とする。
